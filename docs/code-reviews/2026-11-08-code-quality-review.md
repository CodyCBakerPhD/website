## Summary

The repository is small, consistent and unusually well guarded for a personal site. The build refuses to publish a broken page: every record is validated against a JSON Schema generated from the LinkML source of truth, a repeated tag, a dangling logo, a link to a record that does not exist, a repeated element id, a misplaced placeholder or a record missing from the display order all fail `npm run build` with a message naming the file and the slot (`src/build/records.ts:140-203`, `references.ts:115-134`, `projects.ts:92-117`). Record text never reaches HTML or LaTeX unescaped (`src/build/html.ts:16-23`, every renderer; `scripts/render_cv.py:40-64`). CI proves the generated files are reproducible (`validate_records.yml:52-55`), enforces three independent semantic versions (`check-version-bump.mjs`), checks every link on the built pages daily, and builds both PDFs on every pull request so a record that overflows the one-page resume fails the build (`cv/one_page/cody_c_baker_resume.tex:19-24`). The CV follows the site's single-source principle: Summary, Projects, Data Curation and Publications are rendered from the same records into the pages and both documents (`scripts/render_cv.py`, `cv/records.toml`). Comments say why rather than what, with the project's rule written down in `AGENTS.md` and followed.
